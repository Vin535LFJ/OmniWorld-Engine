## OmniWorld Engine 现在是什么

**一个开源运行时，让感知模型、世界模型、仿真器、渲染器、智能体共享同一个"活着的世界状态"——谁在什么时间、哪个实体、归谁管、有多确定，都有明确契约，整件事可以被测量。**

## 为什么它应该存在

2025–2026 年，"交互式世界模型"（输入动作就能走进去的那种 AI 世界）突然成为一个领域。但出现了一个奇怪的浪费：**每一个评测/研究团队都在自己手写同一套"闭环基础设施"**——动作适配、状态格式、和仿真器对接的胶水。NVIDIA 把工业版的这类运行时做出来了，但专有、只服务自家生态；学术界和中小团队没有任何可用的开放版本。OmniWorld 就是那个开放版本，第一站是评测社区。

## 现在进行到哪

```
第 1 周（已完成）：方向定案 + 文档收敛 + 代码入库      ✅
第 2 周（现在）：写 WorldState v0 + 确定性小世界       ← 你在这里
第 3 周：两个感知模型接入 + 闭环跑通
第 4 周：跑基准 + 三条证伪判据的 Gate 1 判定
```

Gate 1（第 30 天）三条判据：闭环 ≥30Hz（你的 RTX 4060 上）；换个感知模型只改一个适配器文件；指标能区分"正常模型"和"故意造假的模型"。**任何一条失败，方向就要被修改——这是设计好的。**

零件都有着落：MVP 全部核心组件已选定开源件（ONNX Runtime / RT-DETRv2-S / Depth-Anything-V2-Small…，许可逐一核验），只有四处"决定性/契约"核心自写——详见 [05 篇](05-组件从哪来.md)。

## 如果不成立呢

第 6 个月：没有外部兴趣信号**且**没有敲门砖证据（如向评测社区仓库提交的 PR 被 merge）→ 降级为个人研究仪器，停止平台化投入。第 12 个月：两者仍都为零 → 冻结扩张。**项目不会失控长大；而且就算生态位失守，过程中的技能与公开工件本身就是你的回报（双轨目标，2026-09-24 确认）。**
