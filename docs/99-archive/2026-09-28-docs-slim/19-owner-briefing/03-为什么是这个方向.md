## 四个候选方向，一句话对比

- **A 纯 GPU Runtime**：工程做得好，但没人会为了"又一个快的管道"来用它——否决。
- **B 完整 World Substrate**：你最开始设想的样子。方向感正确，但正面撞上 NVIDIA Mega，且平台化需要生态团队——单人不可行。
- **C 自己做世界模型**：要数据要算力要团队——否决。
- **D 评测优先的 Grounding Loop Runtime（选中）**：拿 B 里最硬的技术内核（共享世界状态 + 契约 + 实时闭环 + 可测量），只从需求已被实证的那群人（评测社区）进入。**D 做成了就自然长成 B；D 失败了有明确的停损点。**

## 核心命题（你可以拿去检验的一句话）

> 交互式世界模型要成为"环境"和"模拟器"，但没有开放系统让它们与真值仿真器、渲染器、智能体共享一个活的、带契约的世界状态——这个能力要么锁在 NVIDIA 专有栈里，要么在每个评测项目里被重复手写。OmniWorld 是它的开放版本。

## 这套决策的"反方证词"（保持清醒用的三条）

1. 需求是**间接实证**的：没有人公开喊"我要中立 world runtime"——证据是评测项目的重复劳动和公开抱怨。所以 Gate 2/3 才以真实外部信号作为生死线。
2. **WorldFoundry** 是最近的开源邻居（模型中心的训练/评测共享栈）。差异化主张（我们是状态中心的实时闭环）必须在第 1–2 个月的对比 ADR 里站住，站不住就要重新定位。
3. 如果 World Labs 把 SceniX 的仿真引擎开放 + World API 加上活状态——它会正面成为"生成式世界 runtime"。这条被列入 research queue 持续盯防。
