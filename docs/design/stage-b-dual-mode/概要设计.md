## 2. 裁决记录（共创进行时逐轮追加；冻结后此节为设计历史）

### Round 1（2026-10-16，owner 确认全部推荐）

1. **分位数下沉库内**（原简报 Q1）：p50/p95 由库循环层计算并暴露接口，runner 只调用；原始微秒样本仍由 loop 保存。依据：性能模式的容差/延迟判读必须程序化（pre-rebuild Gate 1c `discrim ≥ 0.30` 程序化先例，简报 §3-6）。
2. **ECE 判据与阈值沿用旧值**（Q2）：good = 正确 id 且 transform 误差 ≤ 0.05；Gate 1c 分离线 ≥ 0.30。契约⑦语义一字未改，沿用保证与 pre-rebuild 0.9617 的可比性。
3. **模式 + 环境元数据进机器可读工件**（Q3）：mode 开关与环境元数据写入 JSON 工件（Markdown 报告层引用同一值，写入口单一）。ADR-0009 只约束报告层，进工件是加码落实。
4. **延迟预算挂点 L1 定、初值留切片内**（Q4）：挂点 = TickLog 的 stage_latency（契约⑨载体）+ FrameMeta 的 backend/device；v1 初始预算取对齐运行 p50 × 2，由延迟计量切片实测标定（两棵树都从未定过数值，不拍脑袋）。
5. **噪声 stub 采纳 pre-rebuild 票据 03 定义**（Q5）：注入微小浮点噪声的 stub 适配器，容差窗口内 → 过、超窗 → 判红；不依赖真模型与 ONNX Runtime；**它不是** ADR-0009:16 意义上须声明容差窗口的 GPU 组件——它就是窗口的判据本身。
