## 2. 裁决记录（冻结于 2026-10-16；此节为设计历史）

### Round 1（2026-10-16，owner 确认全部推荐）

1. **分位数下沉库内**（原简报 Q1）：p50/p95 由库循环层计算并暴露接口，runner 只调用；原始微秒样本仍由 loop 保存。依据：性能模式的容差/延迟判读必须程序化（pre-rebuild Gate 1c `discrim ≥ 0.30` 程序化先例，简报 §3-6）。
2. **ECE 判据与阈值沿用旧值**（Q2）：good = 正确 id 且 transform 误差 ≤ 0.05；Gate 1c 分离线 ≥ 0.30。契约⑦语义一字未改，沿用保证与 pre-rebuild 0.9617 的可比性。
3. **模式 + 环境元数据进机器可读工件**（Q3）：mode 开关与环境元数据写入 JSON 工件（Markdown 报告层引用同一值，写入口单一）。ADR-0009 只约束报告层，进工件是加码落实。
4. **延迟预算挂点 L1 定、初值留切片内**（Q4）：挂点 = TickLog 的 stage_latency（契约⑨载体）+ FrameMeta 的 backend/device；v1 初始预算取对齐运行 p50 × 2，由延迟计量切片实测标定（两棵树都从未定过数值，不拍脑袋）。
5. **噪声 stub 采纳 pre-rebuild 票据 03 定义**（Q5）：注入微小浮点噪声的 stub 适配器，容差窗口内 → 过、超窗 → 判红；不依赖真模型与 ONNX Runtime；**它不是** ADR-0009:16 意义上须声明容差窗口的 GPU 组件——它就是窗口的判据本身。

### Round 2（2026-10-16，owner 裁定 Q6=C，Q7 全认）

6. **F2 修复法 = 场景配置化（C）**：`bounds` 策略进 RunConfig（无默认值），v1 只装 `none` + `wall` 两值。理由：① `none` 保留使 2026-10-14 对齐基线（8 实体无墙 64×64）可复现，ADR-0009 性能承诺以固定输入为前提；② `wall` 提供弹墙的全部评测信号（旧 Phase 1 实证：自由段可学、墙反弹错，误差随生产者能力分离）；③ 回绕直接排除（瞬移对所有模型同等不可预测，等于往 ECE 灌场景噪声）。
7. **F2 子决策四项**：① **边界量取常数**（v1 = 0.02，与默认 footprint 对齐），Entity `extent` 字段延后（Usage-driven：无消费者不加字段；加则动三处哈希枚举）；② **实现落点 WorldState `step()` 内**（“带边界的推进”仍是状态推进职责，TruthWorld 调用面零改——避开 TruthWorld 侧 friend 写面歧义；bounds 经 RunConfig 由 LoopDriver 在构造时注入 WorldState，注入点为构造参数而非公开写面）；③ **补 clamp/不变式测试**（旧实现“注释写 clamp 但无 clamp”、单次反射界内不变式无测试守护——已记录偏差，移植时补齐“单轴单 tick 恰一次反射”不变式）；④ **边界事件进 TickLog**（F1 的 ECE 分组口径需要区分场景事件误差与模型误差；具体字段形态留 §4 结构节）。

## 3. 模块划分与独立性论证

| 模块 | 本阶段增补 | 内聚 / 耦合论证 |
|---|---|---|
| `loop` | 逐 stage 延迟原始样本 + **分位数下沉接口**、模式派发、bounds 构造注入、JSON 工件写入口（mode + 环境元数据 + 分位数） | 仍是唯一编排者；依赖单向汇合不变 |
| `world_state` | 新增构造参数 `BoundsPolicy`；`step()` 实现带边界推进（镜像反射 + 速度取反），既有只读面与 friend 通道不动 | “状态 + 推进”单一职责；边界是推进规则的一部分，不是新职责 |
| `truth_world` | **零改动**（Round 2 #7② 构造注入绕开 friend 写面） | 唯一作者纯度保持 |
| `metrics` | **per-producer ECE**：按 producer 分桶；report 键带 producer 维度（聚合键与分解键平铺、排序确定） | 深模块单入口不变；聚合与分解同层呈现（反模式 #13 的正面兑现） |
| `perception` | **零改动** | 接缝稳定性的阶段 B 反面证据 |
| `apps/omniworld_loop` | `--mode` 开关（默认 reference）、工件含 mode + 环境元数据、分位数改调库接口 | 薄 runner，只管 IO 与呈现 |
| `tests/ow_tests` | slice07：容差自证（比较器 + 参数化噪声 stub 测试替身）、分位数行为与口径、per-producer ECE 精确性、wall 不变式 | 行为 + 确定性成对（problem-log 002）；聚合附分解（#13） |

**耦合论证**：所有跨模块依赖仍单向汇入 loop；`tolerance` 比较器为 loop 的私有子件（`src/tolerance/`），输入输出皆纯数据，无回边。

## 4. 接口签名（C++20 级）

```cpp
// ---- loop/driver.hpp 增补 ----
enum class RunMode { Reference, Performance };          // CLI: --mode reference|performance（默认 reference）
struct BoundsPolicy {                                   // 无默认值：调用方显式
  enum class Kind { None, Wall };
  Kind kind;
  float margin;                                         // Kind::Wall 必填；v1 取 0.02（与默认 footprint 对齐，文档写明耦合）
};
struct RunConfig { /* 既有字段不变 */ RunMode mode; BoundsPolicy bounds; };  // 两者均无默认值

struct TickLog { /* 既有字段不变 */ std::size_t boundary_events = 0; };     // 契约⑨ 追加字段（Round 2 #7④）

// 逐 stage 原始样本（库内保存，保真）+ 分位数接口（口径 = 旧 runner：排序后线性插值）
using StageSamples = std::map<std::string, std::vector<double>>;
struct Percentiles { double p50; double p95; };
std::map<std::string, Percentiles> percentiles(const StageSamples&);

struct RunReport { /* 既有字段不变 */
  RunMode mode; BoundsPolicy::Kind bounds;
  std::map<std::string, Percentiles> stage_percentiles;   // 分位数下沉的呈现面
};

// ---- world_state/world_state.hpp 增补（接口最小化） ----
class WorldState {
 public:
  explicit WorldState(BoundsPolicy bounds);               // 唯一新增：构造参数（注入点，非公开写面）
  /* 既有只读面与 friend 通道全部不动 */
 private:
  BoundsPolicy bounds_;                                   // step() 内消费
};

// ---- metrics：report() 键约定 ----
// 聚合键 "ece"；分解键 "ece:<producer>"（平铺、std::map 排序确定）——聚合与分解同层（#13）

// ---- tolerance（loop 私有子件，src/tolerance/） ----
struct ToleranceWindow { std::string metric; double abs_tol; };            // 每指标一窗（含 "ece:<producer>" 分解键）
struct ToleranceVerdict { bool pass; std::vector<std::pair<std::string,double>> deltas; };
ToleranceVerdict compare_within_tolerance(const std::map<std::string,double>& a,
                                          const std::map<std::string,double>& b,
                                          const std::vector<ToleranceWindow>& windows);
// 噪声 stub：测试替身（参数化噪声幅度），先例 = slice04 AlwaysReject / slice06 ThrowingPerception；
// 不进 src/——它是容差窗口的判据工具，不是参与者家族成员（Round 1 #5）
```

## 6. 非功能需求细化（阶段 B 适用部分）

- **参考模式逐字节不变**（退出判据）：B1–B5 每一步后，参考模式同 seed 逐字节复现必须保持；墙钟永不进哈希。
- **工件纪律**：性能模式数字可发表但必须带 mode + 完整环境元数据（ADR-0009；写入口在 runner 单点）。
- **无默认值纪律**：`RunMode`/`BoundsPolicy` 无默认值；默认只许存在于 CLI 参数解析层（reference/CLI 显式选择）。
- **诚实标注**：v1 性能模式尚无真实 GPU 组件——模式差异体现为工件标注与容差机制，**不得假装 GPU**（R-B2）。
- **零依赖与 hook**：引擎零外部依赖不变；新增文档/图表全量过 `tools/mermaid_lint.mjs`（pre-commit 强制）。
