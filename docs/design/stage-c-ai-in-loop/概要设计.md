## 1. 本阶段目标与成果

ONNX Runtime 经 CUDA EP 把**真实模型**（RT-DETRv2-S / Depth-Anything-V2-Small）接入感知接缝——第一次"真 AI 在环"、第一次外部依赖、第一次 GPU 加速路径。出口判据（L0 §4 原句）：**真模型单文件接入、核心零改动 + 性能模式延迟预算报告**。附带关闭判据 (c) 的在环部分（problem-log 006/007 两轮指向"真实模型场景才有关闭条件"）。

## 2. 裁决记录（冻结于 2026-10-16）

### Round 1

1. **范围三项全入**：(a) ONNX 双模型接入；(b) 架构候选 #3（Camera 并入 Observation、分辨率属性彻底化）；(c) 判据 (c) 重测关闭尝试。
2. **框架 = ORT 先行、TRT 预留**（owner 问“可不可以两个一起”）：ONNX Runtime 作为 API 层，CPU EP（参考路径）+ CUDA EP（性能路径）先行；**TensorRT 以 ORT TensorRT EP 形态预留枚举、不实现**——Windows 分发近况需研究 note 核验（NVIDIA 收缩 Windows TRT 安装包），顺序上排在 CUDA EP 基线实测之后（延迟优化先有基线才值得做）。理由：单一集成栈，adapter 代码零分叉。
3. **适配器内双 provider**：每个真模型适配器内部同时持有 CPU EP（参考模式、逐字节）与 CUDA EP（性能模式、容差 + 延迟预算）——参考模式 oracle 属性延续到模型侧（ADR-0009）。
4. **容差政策原则先定、数值切片内**：窗口 = 该组件目标机连续两次独立运行观测到的最大抖动 × 2，随切片实测标定并写入 regression 报告（沿用 B2 做法）。

### Round 2

5. **模型文件管理**：两 ONNX 文件不进 git；`tools/fetch_models` 获取脚本 + SHA256 记录于研究 note；许可随附记录。
6. **EP 选择在运行时**：CLI `--ep cpu|cuda`（默认 cpu = 参考语义；性能模式显式 `--mode performance --ep cuda`）——ADR-0009 双模式由运行时开关表达。

## 3. 模块划分与独立性论证

| 模块 | 本阶段增补 | 内聚 / 耦合论证 |
|---|---|---|
| `perception` 接缝 | 两个真模型适配器（各单文件）：RT-DETRv2-S / DA-V2-Small；每文件内部双 provider | 参与者单文件不变式延续；provider 是适配器内部细节，不进核心 |
| `observation` | Camera 并入 Observation、分辨率属性彻底化（候选 #3） | 观察仍是唯一"生产者视角"；相机是观察的组成，不是外部类型 |
| `loop` + `apps` | `--ep` 选择 + 模式×provider 组合派发 | 编排者唯一；provider 选择不做进核心分支 |
| 构建层 | `OW_WITH_ONNXRUNTIME` 选项（默认 OFF）；ORT 仅链入性能路径 | 参考模式零外部依赖不变式的构建级证明 |
| `metrics` / `report` | 零改动 | B4 per-producer ECE 直接服务判据 (c) 重测 |
| `tests` | slice12–15 | 行为 + 确定性成对 |

**耦合论证**：跨模块依赖仍单向汇入 loop；ORT 依赖被关在感知适配器文件 + 链接行内，核心模块对 ORT 零 include。

## 4. 接口签名（C++20 级）

```cpp
// ---- perception 真模型适配器（单文件；内部双 provider） ----
enum class ExecProvider { CpuEp, CudaEp, TrtEp };  // TrtEp 预留（研究 note 核验后启用）
// 适配器仍实现 PerceptionAdapter（observe(Observation) -> Proposal[]）：
//   provider 由运行时 RunConfig.ep 选择（Round 2 #6）；
//   CPU EP 走参考模式路径（逐字节），CUDA EP 走性能模式路径（容差 + 预算）。
// Observation 仍只经 render() 产出；多分辨率已是其属性（阶段 A slice 02 + C2）。

// ---- observation（C2 后） ----
struct Observation {                  // Camera 并入后：观察自带相机与分辨率
  Tick tick;
  Transform view_pose;                // 观察者位姿 = 契约⑧ 的相机
  FrameMeta meta;                     // backend/device/format/dims（性能模式如实标注）
  std::vector<std::uint8_t> rgb;
  std::vector<std::pair<EntityId, Visibility>> visibility;
  int width; int height;              // 分辨率 = 观察属性（模型分辨率由适配器按需取）
};
// render(state, tick, cfg, pose)：cfg.width/height 已是参数；224 无默认残留。
```

## 6. 非功能需求细化

- **参考模式零外部依赖不变**（退出判据之一）：默认构建不链接 ORT——C1 用构建级断言证明。
- ORT 仅链入性能路径；核心模块对 ORT 零 include。
- FrameMeta 的 backend/device 在性能模式如实标注（契约⑧ + ADR-0009）。
- 每个 GPU 组件落地时声明容差窗口（ADR-0009:16；原则见 Round 1 #4）。
