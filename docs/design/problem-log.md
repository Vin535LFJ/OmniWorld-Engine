## 001 · Mermaid 时序图解析报错：参与者命名撞了语法关键字（2026-10-12）

- **现象**：L0 总体设计的「Tick 主循环」时序图渲染失败，报错 `Expecting '+', '-', 'ACTOR', got 'loop'`，整图不显示（owner 在 GitHub 预览时发现）。
- **定位**：参与者命名用了 `Loop`，与 Mermaid 时序图的语法关键字 `loop`（循环块）撞名且大小写不敏感，解析器把它当关键字而非参与者；另外消息文本里的 ASCII 括号/方括号/花括号 `()[]{}` 属于语法字符，会干扰文本解析。
- **决策与理由**：① 参与者改名 `DRV`，彻底避开关键字族（loop / alt / opt / par / rect / break / note…）；② 消息文本统一用全角（）「」替代 ASCII `()[]{}`——全角标点是 Unicode 字符，不在语法字符集内。命名避开 DSL 关键字 + 文本避开语法字符，一次修复两个隐患。
- **教训**：给图表工具（本质是 DSL，Domain-Specific Language，领域特定语言）写脚本时，**标识符先查该语言的关键字表**——"能起的名字"和"该起的名字"是两回事。这条直觉可迁移：SQL 列名、配置键名、任何 DSL 标识符都要先想关键字冲突。

## 002 · 确定性测试在空实现下"平凡通过"（2026-10-13）

- **现象**：切片 01 红相位（实现故意留空）跑测试，8 处断言失败——但 `hash_state(wa) == hash_state(wb)`（同 seed 两遍一致）这条**居然通过了**。
- **定位**：两个空实现的世界状态完全一致（都是空的），哈希当然相等。"同输入 → 同输出"在实现什么都不做时天然为真——**确定性断言本身无法证明系统做了任何事**。
- **决策与理由**：测试分组设计成行为断言与确定性断言**成对出现**：`tick==10 且 pos==2.5`（行为）与 `hash(同 seed 两遍)==`（确定性）缺一不可；红相位把两者同时暴露（行为失败、确定性平凡通过），绿相位两者同时转绿才可信。
- **教训**：这是测试设计的一般规律——**"不变式断言"必须搭配"进展断言"**（数学上：不变量在零状态下总成立）。任何"每次结果都一样"类的测试，要么配一个"结果确实变了/动了"的测试，要么它什么都不守护。迁移场景：幂等性测试、缓存命中测试、序列化往返测试。

## 003 · C++20 兼容性疑虑：用一次降级实验代替争论（2026-10-14）

- **现象**：owner 注意到"很多项目还在用 C++11、C++17/20 很少见"，担心 C++20 兼容性差（第二次提出此关切；第一次按策略答复，本次补上实验证据）。
- **定位**：① 事实核查——重建至今的代码（core / world_state / truth_world）**零 C++20 专属特性**，全部是 C++11 级设施（struct / enum class / uint64 算术 / 模板）；"C++20"是 CMake 的一个设置，不是代码的依赖。② "很多项目用 C++11"是存活偏差——C++11 已 15 岁，那个年代起步的代码库因 ABI/消费者兼容约束留在原地；本仓库是单机应用、无外部链接方，不共享该约束。
- **决策与理由**：做实验而不是辩论——把 CMake 的 `CXX_STANDARD` 20 改到 17 重建：**一次通过，ctest 2/2 全绿**；恢复 20 再验一遍同样绿。结论：保留 C++20 设置（工具链已实证 + 代码未依赖新特性 + 降级路径一行可切），boring-core 纪律不变。
- **教训**：兼容性问题要用**降级实验**回答（改一行、编一次、跑测试），不要用观点争论；"设置里选的版本"与"代码实际依赖的特性"是两件事——定期用实验确认这个差距，就是把兼容风险钉死在纸面上。

## 004 · 自注册宏撞上 token-paste：带限定名的类型不能过宏（2026-10-14，切片 03）

- **现象**：`OW_REGISTER_PERCEPTION("blob_detect", ow::BlobDetect)` 编译炸出一串错（`make_ow` 不是命名空间 / 类型重定义 / 未定义基类——症状完全不像根因）。
- **定位**：宏对参数做 `##` 粘贴（`make_##TYPE` → `make_ow`）：宏参数被当作**裸标识符**拼接，`::` 处断开；而我把类藏进了匿名名字空间，裸名又不出作用域。两种写法单用都行，叠一起就死。
- **决策与理由**：约定——注册宏的 TYPE 参数必须是不含限定的裸名，且宏调用点放在同一 namespace 内。症状与根因相隔两层，这是宏错误的通病。
- **教训**：自注册宏一族的三条坑齐了：① MSVC 静态库丢注册对象（用 OBJECT 库）② 跨 TU 静态注册顺序不定（枚举按名排序，不靠注册序）③ token-paste 不吃限定名（裸标识符约定）。可迁移到一切注册/反射/TEST 宏场景。
