## Context

方向重开解决了"项目往哪走"，但没有触及"失去把握"的另一层根因：**旧实现是 AI 快速产出、owner 从未共同设计的黑盒子**。owner 于 2026-10-12 明确：已有代码可以放弃、全部重来，但过程必须按软件工程规范（总分结构：总体规划 → 各阶段目标成果 → 逐层详细设计），且要能"像做软件架构设计一样"深度参与、产出可复盘可面试的痕迹。owner 自述不了解软件工程/架构设计——因此过程本身承担教学职责（每步附规范注解，学规范于做事之中）。

## Decision

1. **白纸共创重建**：旧引擎实现（src 除 runtime_probe 约 2,013 行 + apps 277 + tests 250）从工作树删除，只留 git 历史 + `pre-rebuild` tag；旧 `.scratch/phase2-ai-in-loop/` 六张票归档至 `docs/99-archive/`。runtime_probe（1,118 行，独立硬件探针，不含引擎设计）保留。
2. **总分三层设计文档体系**（`docs/design/`）：L0 总体设计（总体规划 + 各阶段目标成果表 + World Contract 语义设计）→ L1 阶段概要设计 → L2 切片详细设计，加横切 problem-log。模板裁剪自 GB/T 8567（概要/详细设计说明书）+ C4 架构分级 + UML（Mermaid 绘制），与 IEEE 1016 交叉对照；落笔模板时用 `research` 核对标准原文，不凭记忆硬写。
3. **设计先行（新操作规则）**：任何代码切片动工前，必须有该切片经 owner 批准的详细设计（L2）；每层设计以 owner 批准为冻结条件，冻结后变更走 ADR。
4. **World Contract 白纸重设计 + 后视镜 delta 审查**：契约语义从第一性原理重设计（owner 2026-10-12 拍板）；设计冻结后对照 v0.1 与 2026-10-09 架构评审的洞见（如"裁决结果应携带它裁决的内容"）——重合处为双重验证，差异处逐条写理由落 ADR。旧文本只经后视镜进入新设计，不作为默认起点。
5. **重建对照基线**：旧实现的历史数字（1106.7 Hz / ECE 分离 0.9617 / 五模型 divergence 分离）作为阶段 A 出口的对齐基线（tag `pre-rebuild` 可查），并要求解释任何差异。
6. **技能映射（owner 要求显式化）**：mattpocock skill 组承载软件工程思想，本过程映射——设计共创轮 = `grill-with-docs`；标准核验 = `research`；切片生成 = `to-tickets`；切片实现 = `implement` + `tdd`；双轴审查 = `code-review`；阶段复盘 = `retro`；过程路由 = `ask-matt`；概念中途不解 = `wait-what`；系统学习某规范 = `teach`。

## Consequences

- Gate-1 证据需要重新挣得（阶段 A 出口 = 对齐报告）；重建期间仓库无可运行引擎代码，仅 runtime_probe 保持可构建。
- ADR-0008 的"实现资产保留"条款作废；其方向/目标函数/Gate 体系/术语全部维持。
- 活跃文档从"三份核心"扩为"三份核心 + `docs/design/` 设计层"（owner 明确要求的设计文档，符合 PLAN 文档纪律的用户要求例外）。
- problem-log 随实现持续生长，条目为"现象 → 定位 → 决策 → 教训"，兼作面试复盘素材（STAR 结构）。
