# 可复现性双模式：参考模式逐字节，性能模式容差

Status: accepted（2026-10-10）

原铁律"同 seed 必须逐字节复现"是数值主张可信度（任何人 clone 后跑同一命令应得到与报告一字不差的数字）与调试可重放性的基础，也是评测功能的正确性前提。但 GPU 推理天然非逐字节——cuDNN 自动调优可能逐次选择不同算法、原子加的执行顺序不定、并行浮点规约顺序受调度影响；同样的输入跑两遍，输出在小数点后若干位抖动，这是浮点并行计算的物理现实而非 bug。Phase 2 的 ONNX 换装将首次引入 GPU 路径，两条规则必然冲突：若都保留，契约回归测试会因噪声随机变红。

决定把一条铁律拆为两条各司其职的承诺：

- **参考模式（Reference Mode）**：纯 CPU，现有代码路径。保持逐字节复现，是契约回归的唯一 oracle——判断"什么是对的"永远以它为准。CLI 默认。
- **性能模式（Performance Mode）**：GPU 推理及后续 GPU 组件。承诺"固定 seed + 固定输入 → 容差窗口内输出 + 延迟预算达标"，回归判据为容差比较而非字节比较。CLI 以模式开关区分。

## Consequences

- 可复现主张不损失（参考模式），GPU 数字可发表（性能模式，报告必须标注模式开关 + 完整环境元数据）。
- World Contract v0.1 字段语义零改动；本 ADR 只定义运行模式层的可复现性承诺分层。
- 后续 GPU 组件（P3 NVDEC、P4 CUDA）沿用同一双模式纪律：每个 GPU 组件落地时必须同时声明其容差窗口。
