# W03 · 切片开发（slice development）

> **薄规格 + 指针**（owner 2026-10-15 决定）。
> 流程主体**已经在** [`workflow-manual.md` SOP-1](../docs/agents/workflow-manual.md) 里规格化，本文件**不复制**它——
> 复制会造成同一事实两个来源（本仓库明令禁止）。
> 本文件只补 **workflow 层**：它作为一个 loop 的触发、检查点与衔接。

---

## Trigger

**事件触发**：`CURRENT.md` 指向了一张 `Status: ready-for-agent` 的票据。

## Checkpoint

**一个硬门禁 + 一个收尾确认**：

1. **L2 批准（硬门禁，不可跳过）**：`design-review → implementing` 只能由 owner 批准触发。
   brief 形态：接口签名 + 测试计划 + 边界情形 + 与本切片无关的模块清单（证明范围）。
2. **收尾确认**：走查后的证据包（diff 范围 + 测试输出 + 票据勾选）。

## 输入 / 输出

| | |
|---|---|
| **输入** | `CURRENT.md` → 票据 → `.scratch/<feature>/spec.md` → 该阶段 L1 → 前序切片 L2 → 相关代码 |
| **输出** | 一个通过全部门禁、有证据、已收口的切片 |

## 步骤

**按 SOP-1 执行**（9 步：定向 → 读 → 写 L2 → 请批 → TDD → 全量验证 → 走查 → 记证据 → 收口）。
细则、出口判据、DoD 清单**全部以 SOP-1 为准**，此处不重述。

本规格只追加三条：

1. **开工前跑 W00**：`bash scripts/state-check.sh`——确认起点干净（未跟踪的产出、未提交的改动会污染本切片的 diff 走查）。
2. **收口后更新 `CURRENT.md`**：指向下一片，或在阶段末指向 W02。
3. **遇到跨切片的设计问题**：停下走 ADR，不要在切片内"顺手改契约"。

## 完成判据（Definition of Done）

以 SOP-1 的 DoD 为准。**本规格不另立一套**——两套 DoD 必然漂移。

## 与其他 workflow 的衔接

```
W03 切片开发 ──最后一片 done──▶ W02 阶段收口 ──▶ 下一阶段
      │                                │
      └────────── 任一步都可能触发 W01 交接 ──────┘
```

## 反模式

| 反模式 | 为什么 |
|---|---|
| 在本文件里重抄 SOP-1 | 同一流程两处描述，改一处忘一处 |
| 跳过 L2 批准 | 仓库硬门禁 G-a；设计漂移后无人能解释为什么这样写 |
| 开工前不跑 W00 | 起点不干净 → diff 走查失效 |
